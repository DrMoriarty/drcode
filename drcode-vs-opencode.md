### DrCode vs. OpenCode — Feature Availability

OpenCode status is checked against the official v2 documentation (opencode.ai/docs: agents, config, plugins, compaction, GitHub pages). "Via plugin" means the official docs do not ship the capability and third-party plugins are the known route; plugin names from older surveys are kept where they were previously verified, but the v2 plugin ecosystem is volatile — treat them as examples, not guarantees.

| Feature (DrCode, out of the box) | What it does | OpenCode status |
|---|---|---|
| **Task-centric pipeline (queue → active → testing → completed)** | The unit of work is a *task*, not a chat session: tasks queue up, auto-start when a slot frees, re-enter the queue when you write into a completed one, and pass through a gated lifecycle | **No** — OpenCode v2 is session/chat-centric; there is no built-in task backlog or gated lifecycle |
| **Tester agent verification with automatic bug filing** | After every completed task, a separate QA agent detects and runs linters/tests/build commands. On failure, it **creates a bug report task at the head of the queue** (bugs always sort first); only the tester can mark a task as passed after verification | **Via plugin** — no built-in verification stage; a custom subagent can review, but there is no pipeline gate and no automatic remediation task. Community plugins (`code-ensemble`, `OpencodePlugins`' Coder↔Tester loop) approximate this |
| **Research agent creates tasks for other agents** | The research agent can **file new tasks on the user's behalf** (`create_bug_report` / `create_feature_request` / `create_research_task`), placed by ordinary queue rules; a branched investigation decomposes into separate research tasks instead of one transcript. It can also search task history and commit documentation edits | **No native equivalent** — no task store to file into. Community plugins (`opencode-agent-teams`, `opencode-orchestrator`, `agent-tdd`) approximate shared boards / delegation / issue generation |
| **Task dependencies (completed AND merged gate)** | A task waits for other tasks; a dependency is satisfied only when it is **completed AND merged** (dynamic git-state check at every promotion attempt, 30 s re-poll — a manual `git merge` unblocks dependents by itself); per-dependency force-start with an audit log | **Via plugin** (`opencode-agent-teams`, `opencode-ensemble`) — nothing native |
| **File-overlap scan on task creation** | Path tokens of a new task's description are matched against unfinished tasks' descriptions and edited files; an undeclared overlap warns the user and the creating research agent, which is expected to chain the tasks with `depends_on` | **No** — no backlog, so no cross-task collision detection |
| **Merge conflict resolution funnel** | On a failed automated merge: the conflict is parked on the task branch (main checkout stays clean), LLM-free triage + provably-safe auto-resolvers (byte-identical, zdiff3, rerere), then a dedicated resolver agent with mechanical checks, the project's test suite and an intent-preservation diff review; falls back to a manual per-hunk zdiff3 screen (`ctrl+m`); nothing is ever committed on a partial pass | **No** — git operations are built in, but no automated triage, no resolver agent, no verification funnel, no conflict UI. Community plugins (`opencode-mad`, `git-reconcile`) approximate parts of it |
| **Task archive search** | `ctrl+f` keyword search across titles, prompts, paths, summaries and events in every task status; the same persisted index powers the research agent's `search_task_history` tool | **No documented built-in** — sessions are listed, but a cross-archive keyword search dialog has historically been plugin territory (`opencode-session-recall`, `agent-historian`) |
| **Per-role model assignment** | A model per role: coding / research / tester / compaction / resolver, picked per project from a shared provider catalog or as free-form custom connections; env override wins over everything | **Built-in (v2)** — every agent (custom or hidden, incl. `compaction`/`title`/`summary`) takes a `model`; per-command models too. OpenCode has no fixed roles, so role separation is achieved by defining custom agents |
| **Dedicated compaction model** | The compaction summarizer can run on a cheaper model, saving tokens on the primary development model | **Built-in (v2)** — `agents.compaction.model` is now documented and honored ("Summary compaction honors agents.compaction.model; otherwise it uses the session's model"). *The old "silently ignored in v2 beta" gap is closed* |
| **Model availability fallback chain** | Per-role ordered chain (primary + up to two fallbacks); providers of the chain are probed at run start under one bounded timeout and the first reachable one serves the request | **No documented equivalent** — a single `model` per agent/session |
| **Provider-level parallel-request throttle** | An optional `max_parallel_requests` per provider caps concurrent outgoing requests across ALL agents of that connection (one semaphore pool keyed by base_url+api_key), with visible "waiting for a free provider slot" service events | **No documented equivalent** |
| **Automatic transport retries + outage mode** | Connection errors / HTTP 429 retried with doubling backoff (5 s → 60 s, 5 tries); on a *sustained* outage the run switches to in-place retrying (cap 15 min) gated by a cheap TCP probe — the machine surviving a gateway downtime loses nothing | **No documented built-in**; a plugin can wrap the provider |
| **Stall watchdog** | A run with no stream/tool events is aborted and auto-restarted after a configurable limit (per-task deadlines under parallel slots); the same nudge is manual (`ctrl+r`) | **No documented built-in** |
| **Restart-safe interrupted work** | Partial transcript survives `Esc`/errors; the next activation resumes the attempt without re-sending the prompt; crashed runs demote to the queue and retry | **Partial** — sessions persist and can be reopened, but there is no documented auto-resume of an interrupted agent run without re-sending input |
| **Failed-queue rescue** | If every queued task failed and nothing is running, the failure exclusion is forcibly lifted and the backlog re-runs — the queue never dead-ends; deterministic HTTP-400 rejections are excluded from the carousel | **No** — no queue to rescue |
| **Parallel development via git worktrees** | Each task gets its own worktree and `drcode/<id>` branch, forked from a pinned start branch (a detached HEAD refuses the isolation); 1–4 queue-driven slots; branch creation audited in service events; duplicate-commit (patch-id) guard in the accept hook | **Built-in worktrees (v2)** — `worktree.directory` config, worktree creation/refresh, plugin-replaceable strategies. But worktrees are created per session manually; there is no queue that auto-promotes tasks into free slots |
| **Read-only research subagents (`delegate_research`)** | Coding/research agents can delegate wide-but-shallow reading to short-lived nested agents whose toolset is strictly read/grep/glob/task-search — no shell, no writes, so they can never race the parent's edits; per-project concurrent caps | **Built-in (v2)** — subagents are first-class (Explore/General, background runs, `subagent_depth`). OpenCode's subagents are permission-*configurable* rather than structurally read-only, and there is no per-project slot cap |
| **Todo checklist** | Feature agents plan multi-step work with `todo_create`/`todo_update` (feature tasks only — bug/research/tester structurally get none); the list renders as a panel and is optionally fed back per-request at the prompt tail (prompt-cache-safe) | **Built-in (experimental)** — `experimental.todo: true` enables a `todowrite` tool |
| **Context eviction marks (`mark_unneeded`)** | The agent marks its own stale tool results; marked results collapse to stubs in ONE batched unload (a single prompt-cache invalidation) at ⅓ of the window and forcibly before compaction | **No** — closest native tools are static `tool_output` line/byte caps and compaction |
| **Context compaction** | At a configurable threshold a tool-less summarizer rewrites the transcript; original user prompts stay verbatim; livelock-guarded (useless-compaction counter stops the pause→compact→resume loop); optional idle-resume force-compaction; model-switch housekeeping (thinking-part stripping + takeover note) | **Built-in (v2), richer in places** — auto/manual compaction with `buffer`/`keep.tokens`, experimental background compaction, and native provider-side compaction (OpenAI Responses) which DrCode does not have |
| **Managed web fetch with SSRF policy** | Research-only `web_fetch`: GET-only, fixed request identity, per-hop SSRF validation (loopback/RFC1918/link-local/metadata IP refused), manual redirect re-validation, size/text caps, untrusted-content framing; per-project host allow/block lists (block always wins) | **Built-in web tools** — `webfetch`/`websearch` with permission rules (`allow`/`ask`/`deny` per resource). No documented SSRF hardening details or allowlist-mode semantics |
| **Product goals registry** | A long-lived roadmap of ideas/goals/milestones (decomposable into sub-goals) lives per project, separate from the backlog; tasks link to goals; the coding agent sees a compact goal block and a scoped `read_goal` tool | **No** |
| **GitHub Issues → local tasks** | `bug`/`enhancement` issues become local tasks on a sync interval; `Fixes #N` appended to the tester's commit; `invalid`/`wontfix` never reconsidered; headless `drcode --git-hub-sync` for cron | **Different shape, built-in** — OpenCode runs *inside* GitHub Actions on `/opencode` mentions: it triages issues, fixes them on a branch and opens PRs, reviews PRs, runs on schedules. It does not pull issues into a local queue |
| **ntfy.sh push notifications** | Pipeline events pushed to ntfy.sh; undelivered messages persisted and retried in strict FIFO order | **Via plugin** — nothing documented natively |
| **Voice input and output** | Push-to-talk dictation (`ctrl+b`) and spoken pipeline announcements over any OpenAI-compatible audio API; PortAudio ships with the package (Linux frozen bundles build an ALSA-only PortAudio) | **No** — not in the official docs |
| **Custom team workflow (hooks + git-workflow.md)** | `.drcode/workflow.py` lifecycle hooks (`on_review` external review can reject and re-queue a task; `on_accepted` can auto-merge — enabling fully automated dependency chains) and `.drcode/git-workflow.md` replace built-in commit rules; fail-closed review; works in frozen bundles | **Via plugin** — OpenCode's plugin system supports hooks and can enforce workflows, and managed `policies` can hard-restrict behavior (stronger than DrCode in the policy dimension) |
| **Custom system-prompt override** | Any built-in prompt can be replaced by dropping a same-named file into `.drcode/prompts/`; AGENTS.md is appended automatically (with a startup offer to create one) | **Built-in** — custom agents carry their own system prompt; instructions/AGENTS.md discovery is native |
| **Clarifying questions with clickable options** | The agent can pause a task with a question and suggested answers rendered as clickable options; the answered task re-enters the queue at the head | **No documented equivalent** |
| **Keep computer awake** | Holds a system sleep assertion (caffeinate / SetThreadExecutionState) while the pipeline has work | **No** — not documented |
| **Auto-cleanup of completed tasks** | Completed tasks older than the retention period (7/30/90 days or never) are deleted at startup | **No** — no task store |
| **Headless CLI one-shots** | `drcode --bug-report DESC` / `--feature-request DESC` / `--git-hub-sync` create tasks or run a sync cycle without the TUI | **Built-in** — `opencode run` provides non-interactive prompting (different shape: a one-shot session, not a task in a queue) |
| **Desktop app** | DrCode Desktop: a pywebview shell spawning the unmodified TUI bundle in an embedded xterm.js terminal — byte-for-byte TUI parity by construction; .app/AppImage/.deb, tag-driven CI builds | **Built-in** — OpenCode ships its own native Desktop app (plus a web app and `opencode pair` remote pairing), which DrCode does not have |
| **Storage hygiene** | Atomic writes everywhere; corrupted JSON → `.bak`, never fatal; transcript sidecars load lazily with an LRU; `.drcode/` gitignore management keeps team-shared files committable | **Not comparable** — different storage model (session data under the OpenCode data directory) |

### Key takeaways

- **The structural differentiator is the pipeline, not any single feature.** OpenCode v2 is session-centric: it has closed most of its former tool-level gaps (per-agent and per-compaction models, subagents, worktrees, todo lists, desktop app), but it still has **no task backlog** — no queue with auto-advancement, no gated testing stage, no tester-authored bug reports at the queue head, no completed-and-merged dependency gate, no archive search over tasks. Everything downstream of "a task is a unit of work the pipeline advances by itself" remains DrCode-only without plugins.
- **The compaction-model gap is gone.** The previous revision called per-compaction model "the sharpest differentiator" because OpenCode v2 beta silently ignored `agents.compaction.model`. In released v2 it is documented and honored — DrCode's per-role model assignment (including a dedicated compaction model) is now matched natively, with the nuance that OpenCode achieves it through free-form custom agents while DrCode ships fixed roles (coding / research / tester / compaction / resolver).
- **Merge-conflict resolution remains the widest gap.** DrCode's funnel (parked conflict on the task branch → LLM-free triage and safe auto-resolvers → resolver agent with a verification funnel incl. intent-preservation diff review → manual per-hunk screen) has no documented OpenCode equivalent, native or plugin.
- **Parallel work: parity on worktrees, difference in driving.** OpenCode v2 has built-in worktree support, but the developer creates and switches them; DrCode's queue auto-promotes queued tasks into 1–4 isolated slots and keeps the tester single so verification never competes for a development slot.
- **Operational robustness is a DrCode cluster, not a single feature:** outage mode with TCP-probe-gated in-place retries, the stall watchdog with per-task deadlines, failed-queue rescue, keep-awake, and persisted FIFO notification retries exist to let long unattended queues survive a night. OpenCode documents none of these natively (its answer to unattended work is GitHub Actions runners).
- **Tester → bug filing** is structural in DrCode: the tester is the only agent that can complete a task after verification, and a failed verification injects a bug report at the head of the queue (bugs always sort first), so fixes are picked up immediately. In OpenCode this requires a multi-agent plugin and has no pipeline to enforce it.
- **Where OpenCode leads:** native provider-side compaction (OpenAI Responses checkpoints), experimental background compaction, managed policies (MDM-grade restrictions), the MCP ecosystem, web search tooling, `opencode pair` remote pairing, and its own native desktop/web apps.
